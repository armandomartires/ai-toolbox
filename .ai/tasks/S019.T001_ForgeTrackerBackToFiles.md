**Depends on**: S011.T034

## Goal

The human asked on 2026-11-15 whether a project on a GitLab or GitHub tracker can change back to files. It could not. Only files → forge was documented, `tracker.sh init` refused to rewrite `tracker.conf`, and nothing read issues back as briefs. This task adds a read-only export and a switch that names its ADR (ADR-0067). It closes no roadmap or ad-hoc item.

## Plan

1. `forge_export.py`: read issues and milestones through `gh` or `glab` (read calls only) and write briefs, reviews, a roadmap fragment, an ad-hoc fragment, `id-map.tsv` and `EXPORT.md` into an empty directory. Check each brief and review against its schema, and list the failures.
2. `tracker.sh export`, and `init --replace --adr ADR-NNNN`, which needs the ADR file.
3. Add gate cases against a fake forge (`fixtures/forge/fake_forge.py`) that refuses any call it does not answer.
4. Add *Changing the tracker back to files* to tracker.md, and point to it from both skills. Versions: project-workflow 8.1.0, project-migration 6.0.1.
5. Write ADR-0067, rebuild the plugin copy, run the gate.

## Acceptance criteria

- [x] `tracker.sh export` writes tasks, reviews, both fragments, `id-map.tsv` and `EXPORT.md` from a GitHub and a GitLab fake. It refuses on a files tracker, into a non-empty directory, or when the CLI is not logged in.
- [x] The export makes only read calls, and it never writes into the repository's `.ai/`. A closed `migrated` issue whose brief the repository already holds is skipped, so it is not written twice.
- [x] A file that fails its schema is listed in `EXPORT.md`, and the export exits 1
- [x] `init --replace` refuses without `--adr`, or with an ADR not in `.ai/decisions/`. With one, it switches the conf and names the ADR in it.
- [x] tracker.md lists the way back in order. Both skills point to it.
- [ ] One export against a real forge, its files checked (the human: `gh auth login`, or `glab` on the host)
