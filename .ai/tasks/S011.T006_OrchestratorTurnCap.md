## Status

- Source: the 2026-11-08 sprint run. Two workers on switchboard changes in a row, a debugger and a builder, both at `maxTurns` 60, were stopped by the engine mid-step. To the person this looked like a communication failure in the orchestration. The coordinator rescued the work by reading transcripts and resuming the agents by hand.

## Objective

When a worker runs out of turns, the coordinator should learn that it did, where its edits are, and how to get them back. On 2026-11-08 each stopped worker's transcript (`~/.claude/projects/<project>/<session>/subagents/agent-<id>.jsonl`) ended on a `tool_result` with no final assistant message. `collect` answered "partial · the worker gave no Status line; read its report" with every field empty and no cause. The uncommitted edits sat in each worker's worktree, unmentioned. A normal retry (re-dispatching the id) would have started a fresh worktree at HEAD and lost them; resuming the same agent with `SendMessage` worked. Three changes follow: caps that fit the work, a `collect` report that names a turn-cap stop and recommends resuming, and an assignment that tells the worker to report before the cap.

## Risks and rollback

- The turn-cap check reads the transcript through `$.session.messages({ agentId })`. If the session cannot read an agent (`{ deny }`), or an agent's last row is a tool result for another reason, `collect` falls back to, or wrongly gives, the turn-cap wording. Only a worker with no Status line is checked, which bounds a wrong call.
- The worktree is found by the engine's naming, `agent-<id>` and `worktree-agent-<id>`, as seen on disk on 2026-11-08. If that naming changes, `collect` says "its worktree was not found" and still advises the resume.
- A non-isolated writer's uncommitted count is the checkout's, not only the worker's; the reason says so.
- The `turn.start` reopen is unverified live. Without it the task stays `partial` until the resumed run ends, and the fence does not hold the resumed run's calls in that time. Reopening also does not re-check the concurrency cap.
- `skills/mod-dev/scripts/mod-dev.sh preview task-orchestrator` stops with `FileNotFoundError` on `claude/preview/scene-kit.ts`: this mod has no preview folder, and the script was already failing on it before this task. Nothing in this change is drawn.
- Rollback: git revert the task commit.
