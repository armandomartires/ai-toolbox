## Objective

In Compass's pane, a one-row handle under the Sprints panel and one under the Sessions panel: the person drags a handle up or down and that panel's height follows; a double press puts it back to automatic.

## Inputs

| Artifact | Expected state |

| `mods/task-compass/` 0.9.2 | `view.tsx` sizes the board from the pane: `room = max(BOARD_FLOOR, max(16, bodyRows) - BOARD_CHROME_ROWS)`; agent-watch's contribution drawn after the board (ADR-0048) |
| `mods/agent-watch/` 0.8.1 (`TASK-0216`: a blank row above its part, the KPI row kept on the desktop) | `contributeSessions` draws the meter and `renderSessions(..., reservedRows 0)`, which sizes from `sessionsLayout({ rows: max(16, bodyRows) })` |
| this build's mod API | `Client` (terminal and desktop tables; not mobile, not vscode) runs a surface module; `surface.onPointer` gets `down`/`move`/`up`, and after a `down` holds the pointer until `up`, past the region's edges; `surface.post` reaches the drawing plugin's own `ui.message` hooks only |

## Findings (2026-11-03)

- **Only a `Client` can be dragged.** Nothing else in the API delivers a pointer move; a `Button` gives presses only.
- **A `Client`'s posts reach only the plugin that drew it**, and a plugin can draw only its own surface modules. So each mod draws the handle for its own panel and keeps that panel's height in its own `$.state`; neither mod reads the other's.
- **The two surfaces measure a drag differently** (spike, live, 2026-11-03). A terminal reports rows from the region where it now is, moved with the panel it sizes, so a move asks for the rows drawn now plus the move's row less the press's; the human: "on cli seems to work ok". The desktop reports them from where the region was at the press: with the terminal's rule it "keeps snapping to far from the drop"; measured from the rows drawn at the press, it "follows the pointer".
- **The desktop does not call the module again between pointer events** unless a `ui.message` hook answers `{ props }`: without that, every move started from the first height and the release sent it back ("it always reverts to the initial position").
- **A surface module's `state` is a copy taken at `setState`, and `performance.now()` starts near 0** (spike, in the kit): the drag's values live in a per-instance map keyed by `surface`, and the double-press window starts at `-Infinity`.

## Risks and rollback

- The desktop's rows are not the terminal's cells: if its `Client` reports `y` in a unit other than the pane's rows, the panel moves faster or slower than the pointer.
- Both measuring rules were seen in a spike, not a kit: a later build that changes either makes the handle drift, and the kit test that pins them still passes.
- The Sessions handle's base is `layout.used`, the accounting's count of the panel's rows; if it is off by a row the terminal drag is off by that row.
- Rollback: git revert the task commit.
