## The obvious check was the wrong check, twice

- **Env vars:** the intuitive check is "is the variable set". It would have
  failed on every fresh clone and in the CI run this session proved works —
  CI has no `.env` and needs none. Replaced with documentation completeness:
  every `required` var in any manifest must appear in `.env.example`.
- **Skills:** the pre-existing check was `grep -q '^name:'`. It could not
  detect a `name` disagreeing with its directory — the defect class behind
  three `_template` registry leaks. Replaced with a parser, because "is the
  description one line" is not a grep-shaped question.

## A test harness that proved nothing

TASK-0014's first proof cloned the repo for isolation — and thereby isolated
itself from the uncommitted change under test. All four cases reported "no
warning", which read as a code bug. The harness was the bug. Fixed by
copying the working-tree script in and asserting the new warning string was
present *before* testing. **A test that clones for isolation may isolate
itself from the change it verifies.**

## Addendum, 2026-09-13 (TASK-0019): one claim from this session was false

The "default branch mismatch" recorded above never existed. `main` was never
created; `default_branch` has been `master` since the first push. Verified by
`GET /repos/:repo` (`master`), `GET .../git/ref/heads/main` (404), and
`git ls-remote --symref origin HEAD` (`refs/heads/master`).

Cause: `gh-create.py` printed `default_branch` from the **repo-creation
response**. With `auto_init: false` there were no commits and no refs, so
GitHub returned the account's default branch *name preference* — a
forward-looking placeholder, not a description of state. Pushing `master`
then made it the default automatically.

This session's own summary claims CI was "verified, not assumed". That was
true of CI and false of this. The distinguishing feature is that the CI
check *polled until a run completed*, whereas the branch claim was read once
from a creation response and never re-checked — then restated twice more with
growing specificity. The log is left intact above; this addendum is the
correction, because a session log records what was believed at the time.
