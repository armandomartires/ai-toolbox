- **Design decision the brief left open, now settled:** the smoke test is
  a **separate script**; `validate.sh` is untouched. Measured first rather
  than asserted — `validate.sh` is 326 ms with zero network invocations,
  and it is the mandatory gate run at the end of every task. The smoke
  test needs the network (`npx -y` fetches upstream) and takes tens of
  seconds. Folding them together would make every task's validation fail
  on an offline laptop for reasons unrelated to the repo. Verified
  afterwards that `git diff tests/validate.sh` is empty.
- Implementation notes:
  - Everything is read from `server.json` — launch command, transport,
    required env — so the harness checks `launch.command` rather than
    restating it. Nothing about ansible is hard-coded.
  - **SKIP is a first-class outcome.** Missing launcher, unsupported
    transport, or unresolvable required env → SKIP, exit 0, and the
    summary prints "SKIP is not a pass - the check did not run."
    Collapsing SKIP into PASS is how a harness like this becomes theatre.
  - Required-env judgement call: ansible's only required var is
    `WORKSPACE_ROOT`. SKIP would mean never testing it; inventing a value
    silently would hide the substitution. The harness supplies the repo
    root for workspace/root/dir-shaped names *and prints a note saying so*.
  - Banner tolerance: the reply scan walks stdout for the first JSON object
    with `id: 1`, so a server printing a banner before its JSON-RPC reply
    still passes. Asserting on "first line of stdout" would be brittle.
  - Only `initialize` is sent, never a tool call — ansible's surface
    includes playbook execution and OS package installs, and a smoke test
    must never be the thing that runs a playbook.
  - Templates are skipped from the outset, pre-empting the leak that had
    to be fixed three times in `sync-registry.sh`.
