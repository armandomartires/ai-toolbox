## What was done

**ADR-0018 accepted.** Ratified on evidence rather than agreement,
following ADR-0019's precedent for showing corrections in place.

The mechanism survived; the reasoning did not:

- **Clause 2's justification replaced.** The ADR argued a superset file
  fails for *semantic* reasons (`permission` and `tools` are different
  models). True, but not the blocker. The real blocker is a **safety**
  failure: a superset file loads in both clients and Claude Code
  **silently discards** an OpenCode `permission:` block, leaving the denied
  tools in the pool. Clause 2 now carries that as its citation, plus three
  concrete prohibitions each traced to an observation — never emit
  `tools:` for OpenCode (one malformed file empties the whole agent list),
  never put `name:` in a role file, emit `model` per client.
- **New clause 8 — the emitter refuses; it never degrades.** The
  substantive addition. A capability term declares which clients enforce
  it; emission fails loudly when a target cannot enforce a declared term.
  Clause 8.3 settles **`git-ops` and `shell-runner` as OpenCode-only
  roles** rather than leaving TASK-0045 to discover it. Clause 8.4 rejects
  both workarounds with reasons and requires a worked example in a future
  ADR rather than improvisation inside a task.
- **Four facts corrected in place**: the overlap is `description` alone
  (not three fields); OpenCode identity is the filename *unless* a `name:`
  field overrides it; unknown keys are *forwarded to the provider* in
  OpenCode, not inert; and `.opencode/agent/` singular also loads.
