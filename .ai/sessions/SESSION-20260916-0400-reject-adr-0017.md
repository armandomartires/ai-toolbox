## Substantive findings while executing

1. **The rejection creates a real gap, and "document" was the right call.**
   ADR-0018 clause 7 names `models.jsonc` the single owner of tier→model —
   and that file is now permanently in another repo. `emit-agents.py` emits
   `model: "{tier:<name>}"` and **no resolver exists here** (verified by
   grep). Harmless today because `model` is optional and no role uses it.
   The documented rule is: **omit `model`**, and **do not add a second
   mapping here** — that is the two-owners defect clause 7 exists to
   prevent, and worse than the gap.
2. **"OpenCode-specific" is substantively correct, not just convenient** —
   worth recording because it makes the rejection defensible on the merits
   rather than only on procedure. `install-tiers.ps1` depends on
   `plan`/`build` being OpenCode built-ins overridable by config while
   keeping their tuned prompts; Claude Code's custom files *replace* a
   built-in instead. And **Codex has no per-role agent definition at all**
   (`codex-cli 0.154.0`, checked here): `codex agents` browses *sessions*,
   there is no delegation concept, and `--profile` layers one config bundle
   rather than named roles.
3. **The two-owner question moved outward rather than disappearing.** After
   TASK-0045, `git-ops` will exist twice on this machine by different
   routes: `install-tiers.ps1` writes a **project-local** copy,
   `install.sh` emits a **global** one, and OpenCode resolves project over
   global. Not a defect and **unfixable from this repo** — the other copy
   belongs to another repo's installer. TASK-0045 now carries an obligation
   to *document* it so a reader finding two files knows why.
4. **`TASK-0045` is a Phase 3 dependency, not only Phase 4.**
   `loops/design-brief/` delegates its step-7 commit to `git-ops`, so the
   design loop cannot run end to end until that role exists. Recorded in the
   brief's deviations.
