# ADR-0027 — Artifact shape has one owner: a schema, generated into templates

## Status
Accepted (2026-09-26)

Task: `TASK-0109`. Supersedes nothing. Narrows nothing.
Constrained by, and consistent with, `ADR-0008`, `ADR-0013` and
`ADR-0018` clause 7 — see **Consequences**.

## Context

Both governance frameworks produce their planning artifacts the same way:
**copy a template file and fill it in.** The template is a document to
imitate — 68 lines of prose guidance in `project-workflow`'s case — and the
author must decide, sentence by sentence, what is instruction to delete and
what is structure to keep.

That mechanism has now failed three measurable ways, counted against the
tree on 2026-09-26 rather than recalled:

1. **The template disagrees with its own skill.**
   `skills/project-workflow/SKILL.md` and `templates/00.CONVENTIONS.md`
   state task files are `S###.T###_Name.md`. The template's own H1 and
   copy-instruction state `S###_SprintName.T###_TaskName.md`. Two owners of
   one fact, in the skill whose governing rule is *"One owner per fact —
   link, never copy."* Nothing detected it, because nothing could: the
   shape is stated in prose in four places per framework.
2. **Instances drift from the template and from each other.** 105 task
   files in `.ai/tasks/`: min 102, mean 272, max 661 lines. `## Inputs` in
   86 of 105; superseded `## Preconditions` in 23, `## Dependencies` in 23,
   `## Expected result` in 19; eleven further one-off headings. Heading
   **order** is ungoverned — `TASK-0108` moved `## Status` to the end and
   nothing noticed.
3. **`.ai/templates/ADR.md` is 71 bytes of bare headings** while real ADRs
   reach 37,140 bytes and routinely carry `## Alternatives considered`,
   `### Why rejected` and `### Reopen trigger` that the template never
   names. The template does not describe the artifact.

**The requirement that forced a decision now**, stated by the human on
2026-09-26: the convention must hold for models from roughly 12b
parameters to frontier. This is the load-bearing observation —
copy-and-imitate degrades with model capability, because every "keep or
delete" judgment is an independent opportunity to drift, and a smaller
model takes more of them wrongly. Fill-a-marked-slot does not degrade the
same way: the slot is either filled or it is not, and that is decidable by
a script rather than by taste.

## Decision

**1. A schema file is the single owner of an artifact's shape.** Headings,
their order, which are required, and whether each is written before or
after the work. One file per artifact kind per framework.

**2. Template files become derived artifacts.**
`skills/project-workflow/templates/{tasks,decisions,reviews}/*` and
`.ai/templates/{TASK,ADR,REVIEW,SESSION}.md` are generated by
`scripts/sync-templates.sh` from the schemas, carry a
`GENERATED … — do not hand-edit` banner, and `tests/validate.sh` fails on
drift. This is the shape `docs/registry.md` and
`skills/unattended-ops/templates/bindings/opencode/decision-standard.md`
already use; it is not a new pattern.

**3. Artifacts are generated, not copied.**
`skills/project-workflow/scripts/new-artifact.sh` emits a skeleton with the
identifier, date, sprint, filename and every heading already correct. The
author writes prose into `<!-- FILL: … -->` slots and never types a
heading, chooses an order, or invents an ID.
`skills/project-workflow/scripts/check-artifact.sh` proves the result
matches the schema, reading the headings **from the schema file, never from
a copy held in the script** — the rule `check-binding.sh` already follows
for `loop.md`'s step numbers, so a schema change never requires editing the
checker.

**4. The generator's `--guidance` flag is a prose-density axis and is
explicitly not a model reference.** Its four levels —
`terse | standard | explicit | literal` — vary only the instruction text
inside `<!-- FILL: … -->` comments. **The filled artifact is identical at
every level**, and `TASK-0109` proves it by generating at all four,
stripping every comment, and diffing.

`SKILL.md` carries a suggestion table mapping model sizes to levels. That
table is **documentation, not a resolver**: nothing reads it, nothing
resolves it, and no tier name appears in any frontmatter, schema or script.
`ADR-0018` clause 7 — model references belong in one place, and that place
is `agent-tiers`' `models.jsonc` in `opencode-customization` — is untouched.
The flag is deliberately **not** named `--tier` for this reason.

**5. Uniformity is enforced as shape, never as size.** The checker and the
gate compare an artifact's heading set and heading order against the
schema's declared list. **No byte or line cap is introduced anywhere.**

**6. The two frameworks keep two separate schema sets.** They share the
engine only.

## Alternatives considered

- **Fix the four prose statements and move on.** Rejected: it repairs this
  instance of the contradiction without removing the mechanism that
  produced it. Four owners becoming four *agreeing* owners is still four
  owners, and `ADR-0013` was raised by exactly this class of drift.
- **A `--tier` flag named for parameter counts (12b … frontier), which is
  what was first requested.** Rejected in favour of `--guidance` after
  finding `scripts/emit-agents.py` already emits an unresolved
  `{tier:<name>}` and `docs/development/authoring-guide.md` explicitly
  forbids closing that gap here (*"Do not close this gap by adding a second
  tier→model mapping here"*). A flag named `--tier` would have created the
  second tier vocabulary that `ADR-0017` was rejected to prevent — even
  though it means something different — because the collision is in the
  name, and names are what drift.
- **A line or byte budget on generated artifacts.** Rejected: `ADR-0008`
  settles it. *"Enforcing an invented number would make this gate the
  author of a requirement rather than the enforcer of one."* A schema's
  heading list is not invented — it is transcribed from what the artifacts
  already contain — so shape is enforceable where size is not. Size falls
  as a consequence and is not measured.
- **Retro-fit the 105 existing briefs to the schema.** Rejected, and the
  argument is already written at `validate.sh`'s `FIRST_CONTRACT_TASK = 20`:
  they are *"records of what happened, not instances of the current
  template; rewriting them to satisfy a rule invented afterwards would
  fabricate compliance."* A new `FIRST_GENERATED_TASK` boundary carries the
  same reasoning forward.
- **Unify the two frameworks now that a shared tool exists.** Rejected:
  `ADR-0013` decided that unification is a large breaking change and that
  the present cost is confusion, which documentation fixes. Sharing an
  engine is not sharing a shape, and this ADR shares only the engine.
- **A general template engine (jinja, `envsubst`, `string.Template`).**
  Rejected: the repo has none, deliberately, and every existing generator
  is `cat` plus a banner. A dependency that needs `pip install` is one the
  hermetic gate cannot run — the argument `check-binding.sh` already makes
  for hand-rolling its YAML subset.

## Consequences

- **Shape becomes mechanically checkable for the first time.** Heading
  drift of the kind that produced 23 stale `## Preconditions` sections now
  fails a gate rather than accumulating unnoticed.
- **Templates can no longer be hand-edited.** Editing one is now editing a
  generated file, and the staleness check will fail. The schema is the
  place to change. This is a real workflow change for anyone used to
  tweaking a template directly, and the banner says so in the file.
- **`project-workflow`'s production mechanism changes**, so its version
  goes to `4.0.0`. A project scaffolded from an earlier version keeps its
  copied templates and is unaffected until it re-scaffolds —
  `templates/reference/skill-maintenance.md`'s copy-never-symlink rule
  already governs that, and nothing here retroactively edits a scaffolded
  project.
- **One stated gap.** The engine lives in `skills/project-workflow/`, so a
  consumer installing **only** `project-migration` gets schemas with no
  generator. Nothing breaks inside this repo, where both skills are
  present. Closing it means a verbatim synced engine copy plus a drift gate
  — the `sync-decision-standard.sh` shape. **Deferred to `BACKLOG.md`, not
  built**, because no consumer has hit it, and building for an absent
  consumer is how the second owner appears.
- **What this does not prove.** That a generated skeleton produces a *good*
  brief. It constrains shape, not content: a schema-conformant artifact can
  still have an empty-headed `## Goal` that says nothing. The checker
  catches a missing heading, an out-of-order heading, a surviving `FILL:`
  marker and an unfilled after-phase section on a completed task. It does
  not read prose for meaning, and must not be extended to try — *"a check
  that guesses fires on correct text and gets deleted."* Do not soften this.

## Clarification (2026-09-27, `TASK-0110`)

**Two statements above were true when written and are now false.** They are
left in place rather than edited, so the record shows what changed.

1. Consequences said *"Only task briefs are gated; ADR, review and session
   schemas exist and generate, but nothing checks the finished files."*
   `TASK-0110` gates all four kinds. That was safe to do immediately because
   the gap was measured before it was planned and there was none: **27 of 27
   ADRs and 30 of 30 sessions already matched their schema**, and 11 of 12
   reviews did.
2. The same section implied the task boundary was settled at 109. It is now
   **24**, lowered only after repairing every brief it newly covered.
   `TASK-0001`–`TASK-0023` remain exempt, unchanged: `ADR-0012` and
   `FIRST_CONTRACT_TASK` own that exemption, not this ADR.

**Two exemptions exist, and are named rather than absorbed into a number.**
`REVIEW-0012` is exempt by name — the only review of twelve that diverges,
and making it conform would mean relocating sections inside a closed
sprint's point-in-time record, which the review schema's own write-once rule
forbids. Honouring a schema by rewriting the artifact it describes is not
compliance. `TASK-0057`'s dead template scaffold was demoted, not deleted,
for the same reason: someone had explicitly retained it.

**Nine briefs were repaired by disclosure, not reconstruction.** Each was
missing a section written *before* the work — `## Likely files` five times,
`## Mandatory validations` twice, `## Execution plan`, `### Attempt 1`. Each
now carries the heading and a dated line saying it was not recorded. The
content was deliberately not rebuilt from git history: a forecast written
after the work is an outcome wearing a forecast's label, which reads as
evidence and is worse than the missing heading.

**A regression this ADR caused, found and fixed by `TASK-0110`.** Turning
the review template into a schema dropped its write-once rule, which lived
in the copy-instruction blockquote and was treated as a copy instruction
rather than the substantive rule it is. Restored to both review schemas.
The lesson generalises: when a template becomes a schema, its prose must be
triaged line by line into *instruction about copying* and *rule about the
artifact*, and only the first may be discarded.
