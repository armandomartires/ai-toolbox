Mod Workflow

A mod is a Claude Code plugin whose hooks module the engine loads. Every change to one under mods/ goes through the nine stages below, each gated by a check, three of them handed to the human. Cyan is the agent, amber the human; colour marks the actor only.

Semver by this repository's rule: patch for a fix, minor for a feature, major for a change to types/index.d.ts that another mod mirrors. Claude Code itself does not check version against semver; it hands users a new copy only when the string changes. Git is the changelog: git log --oneline -- mods/<name>.

One copy of a mod per session

PRECEDENCE · WHAT LOADS
Turn the library copy off while developing. The documented precedence puts a CLAUDE_CODE_PLUGIN_DIRS plugin above an installed or synced one, silently. On 2026-11-03 the desktop app drew the library's task-compass 0.8.0 over the checkout's 0.9.1 all the same, while claude plugin list said the opposite. Read the version line, not the list.
Copy, never link. A junction from a session's dev-mods folder into the checkout kept running hours-old code. dev-mods.py copies as files and mirrors edits; it replaces a link it finds.
Edit the checkout. The dev-mods copy is a mirror, overwritten at the next sync; an edit there would load a second plugin of the name.
When a mod seems not to run. The docs' order: claude plugin validate, /reload-plugins, the /plugin Errors tab, claude plugin list; here, the version line last. A failed hook is skipped and named once in the transcript; every occurrence is in claude --debug.

Not portable. Panes and bands, the kit and the preview built on it, hot reload, the organization library.
Where a port lives. One subfolder per client inside the mod's folder, so the registry keeps one row; needs an amendment to ADR-0040 clause 2. Backlog B-069 (OpenCode) and B-070 (Codex).
