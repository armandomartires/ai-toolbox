# Playbook: the live check of task-compass in Codex (S011.T003)

The human's run of the two open criteria of `S011.T003`
(`.ai/tasks/S011.T003_TaskCompassCodexPort.md`). Tick the boxes in
`S011.T003-codex-live-check-checklist.md` as you go, and hand the filled
checklist back: the agent records it in the brief and closes the task.

## What is being proven

task-compass's Codex bundle (`mods/task-compass/codex/`) has passed its tests
(7 node tests, `tests/test-install.sh` X1–X5) but has never loaded in a real
Codex. Codex draws no UI, so the port is three parts:

| Part | File | Seen when |
|---|---|---|
| A `SessionStart` hook | `hooks/hooks.json` → `scripts/session-start.ts` | the current sprint's open stories are in the session's context |
| An MCP stdio server | `mcp.json` → `scripts/mcp-server.ts` (plain node) | Codex lists a `story` tool, and calling it changes a box in `.ai/GOALS.md` |
| A skill | `skills/board/SKILL.md` | `$board` is offered and shows the board |

## Before you start

- **Node 22.18 or later** on the PATH (`node --version`): the scripts are
  `.ts` run directly by node, with no build step.
- **Codex CLI** installed and signed in with your own account (`codex --version`).
  The Codex IDE extension loads no plugins, so use the CLI.
- **This checkout** at the current `master` (`git -C <checkout> log --oneline -1`).
- A **scratch copy of the board**, so the `story` call changes nothing that
  matters: any folder with an `.ai/GOALS.md`. A copy of this repository's
  `.ai/GOALS.md` in an empty folder works; never commit what the test changes.

## Steps

1. **Install the bundle.** From this checkout: `bash scripts/install.sh --client codex`.
   It copies `mods/task-compass/codex/` to `~/.codex/plugins/task-compass/`
   and prints `mod copied: task-compass -> … (add a marketplace entry for it,
   then restart Codex)`. `bash scripts/install.sh --status` lists it.
2. **Add a marketplace entry naming `task-compass`.** Codex loads a plugin only
   when a marketplace names it. The file is `.agents/plugins/marketplace.json`
   in a marketplace repository (the legacy `.claude-plugin/marketplace.json`
   is read too); a workspace admin imports that repository, or, for your own
   machine, add the marketplace as Codex's plugin docs describe for a local
   one. Check the exact command against Codex's current plugin docs: this
   repository has not run it (that is what this check finds out). Record what
   you did in the checklist.
3. **Restart Codex**, in the scratch folder from *Before you start*.
4. **Context.** Ask: "Which stories are open in the current sprint?" Expect the
   answer to come from the session's start context, matching the sprint's
   `[ ]`, `[>]`, `[?]` and `[!]` lines in that `GOALS.md`, without the model
   reading the file first.
5. **Tool listed.** Ask Codex to list its tools, or run `/mcp`. Expect a
   `task-compass` server with a `story` tool.
6. **Tool works.** Ask: "Use the story tool to mark story <n>.<m> in review."
   Expect that line's box to change to `[?]` in the scratch `GOALS.md`
   (`git diff` or open the file).
7. **Skill.** Type `$board`. Expect the board skill to show the sprints and
   their stories.
8. **Marketplace for the team (the second criterion).** If a workspace admin
   imports a marketplace that names `task-compass`, note who and when; if not,
   leave that box open and say so.

## If something fails

| Symptom | Likely cause | What to note |
|---|---|---|
| No `task-compass` server in `/mcp` | no marketplace entry, or no restart | the marketplace file and how it was added |
| Server listed but fails to start | node older than 22.18, or `${PLUGIN_ROOT}` not expanded | `node --version`, Codex's MCP log |
| No stories in the context | the hook did not run, or no `.ai/GOALS.md` under the session's folder | Codex's hook log, the folder |
| `$board` missing | skills folder not read from the bundle | the bundle path Codex reports |

Do not edit the bundle to make it pass: note the symptom and hand the checklist
back; the fix is a task of its own.

## Hand back

Paste the filled checklist (or its path) into the session. The agent ticks the
live criteria in the brief with your evidence, closes `S011.T003` if both are
met, and otherwise records what failed.
