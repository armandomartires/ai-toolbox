# ai-toolbox-agents

Role agents emitted for Claude Code by scripts/emit-agents.py. Generated by scripts/build-plugin.py; edit agents/ in the repository and rebuild. It depends on ai-toolbox-skills. It ships one hook, the role guard (hooks/role-guard.py, ADR-0062): a PreToolUse hook keyed on the agent type that enforces the shell allowlists, test-path edits, forbidden git commands and confirmations the agent files cannot express. It is started by bash hooks/role-guard.sh and needs python3 (or python) 3.8+ on PATH; without one, calls from this plugin's guarded agents are denied and every other call is left alone. Out-of-allowlist calls are asked until the role-guard.json deny_from date (UTC) and denied from it. The roles it guards ship only here, never in a plain scripts/install.sh emission. The worktree hooks are not here: they are this repo's sibling-worktree rule and come from scripts/install.sh. It ships no permission rules: a plugin settings.json is not a known way to ship them, so scripts/install.sh writes them. Known gaps from the plugin cache: skills and agents were written for an ai-toolbox checkout. unattended-ops, design-flow and ansible-ops point at loops/ (not shipped); the emitted agents cite skills/... paths that resolve only in a checkout; unattended-ops/scripts/check-binding.sh defaults to ../../../loops/unattended-run/loop.md and needs the loop file passed as its second argument. mod-dev is left out (checkout only). The five run-<loop> skills (invoked by hand, never by the model) carry their loop.md beside them (and untrusted-content.md where loop.md cites it), so they work without loops/; they are invoked as /ai-toolbox-skills:run-<loop>. The other loops/ pointers in the skills still do not resolve here.
